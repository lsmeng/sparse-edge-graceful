# sparse-edge-graceful

Code, certificates and manuscript for

> **Edge-graceful trees with few vertices of degree two**
> Lingsen Meng

*Archival DOI:* to be minted on Zenodo at submission (see **Archival** below).

A tree of odd order *n* is *edge-graceful* if its edges can be labelled
1, …, n−1 so that the induced vertex sums are distinct modulo *n*.  The paper
proves, unconditionally, that there are absolute constants *C*, *A* and *n₀*
such that every tree of odd order *n ≥ n₀* with *D* vertices of degree two is
edge-graceful whenever *n > C(D+1)(log n)^A*; under the abelian improvement
of Müyesser and Pokrovskiy's matching theorem the threshold becomes linear, *n > C(D+1)*.

## What is here

    paper/        the manuscript (LaTeX and PDF); numbers.tex, catalogue_table.tex
                  and blocks_table.tex are generated by scripts/paper_numbers.py
    scripts/      the search, the independent checker, the scheduler, the
                  abstract enumeration, the gate, the closure check, the two
                  construction identities, and the constructor
    data/         the context list, the certificate catalogue and its variant
                  tables, the raw solver batches, and the neutral blocks
    REPRODUCE.md  how to rerun every step

The large artifacts are compressed.  Unpack them before running anything:

```bash
gunzip -k data/alphabet_families.json.gz data/alphabet_families_xtok.json.gz data/alphabet_families_xall.json.gz
tar -xzf data/batches.tar.gz
```

`CLOSURE INCOMPLETE` with the open contexts listed.  At the state recorded

## Verification

Certificates are never trusted because of how they were found.  Every family
in the catalogue is re-verified by `scripts/check_alphabet_families.py`, which
rebuilds the cell topology from the row specification, recomputes the outputs,
and re-checks the defining conditions with exact rational arithmetic and at
random integer points.  It shares no code with the search.  At the state
recorded here it reports **5716 total, 5716 PASS, 0 FAIL**.

The families built by the two construction identities (`extend_by_insertion.py`
and `extend_by_neutral_block.py`) are written in the same format the solver
emits and pass through exactly the same checker.

## Requirements

Python 3.10 or later, and [OR-Tools](https://developers.google.com/optimization)
for the search (`pip install ortools`).  The checker, the scheduler, the
enumeration and the closure check need only the standard library.
